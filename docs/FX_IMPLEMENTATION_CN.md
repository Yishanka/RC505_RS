# RC505 RS 0.3：FX 实现、延迟与验证边界

[BOSS 官方参数表 rev.04，第 34–43 页](https://static.roland.com/assets/media/pdf/RC-505mk2_Parameter_eng04_W.pdf#page=34) 是控制语义的第一参考；[完整家族列表](RC505_MK2_FX_CATALOG_CN.md) 保留用户的优先级批注。以下是 RC505 RS 的实际实现，不是 BOSS 源码或实机听感等效结论。

## 路由与共同约定

本轮新增 19 个音频效果家族；每个都能放入 Input FX 或 Track FX，并可编辑、保存为预设、随工程和回放保存。OSC 仍是独立音源；普通音频效果需要输入或轨道音频，没有无意义的钢琴卷帘或音符试听按钮。

新工程的 Input FX 默认按 **A → B → C → D** 串行处理。旧工程如果保存的是 Legacy 路由，仍使用旧分组次序：OSC／旧 MyDelay → Vocoder → Filter → Reverb → 新 Audio FX → Input Roll。Legacy 下新增效果不按所有槽位共同排序；可在 Session／工程设置主动改为 A → D。Track FX 按槽位排列，每条轨道独立启停。

同步的声像、颤音、切片和移调控制序列跟随共同采样时钟，不会因五条轨道长度不同、起点错开或循环回卷而分别重启。Track Filter 的原步进门控仍保留随轨循环的含义。

内部音频链和现代叠录使用有限的浮点余量（保护上限 ±16，即约 +24 dBFS）。中间效果不再一律硬截到 ±1；可以降低推子或通过主压缩收回电平。最终音频输出仍限制到 ±1，并记录削波。失真器、延迟反馈保护和其他算法本身的非线性仍保留。浮点 WAV 快照可以保存大于 1 的采样值；这属于 0.3 的声音变化。

## 新增效果与实际算法

| 类型 | 实际实现与主要控制 | 实际限制 |
|---|---|---|
| Transpose／移调 | 立体声相位声码器，按瞬时频率重映射频谱；−12～+12 半音；可画 1～16 步相对半音序列 | 不改变循环时长；瞬态会变柔，不保留共振峰；不是 BOSS 的 Mode 1/2 |
| Electric／电音校音 | 有界、分散计算的 YIN 单声部检测，半音阶／大调／自然小调吸附，移调、校音速度和稳定度 | 是人声阶梯校音，不是“所有电子音乐效果”的总称；不适合同时输入多个人声，不提供假冒的共振峰旋钮 |
| Harmonist／手动和声 | 指定主音与调式，按音阶求三、四、五、六度或八度和声；独立原声、和声电平及声像 | 单声部检测；无 MIDI 自动和弦；没有硬件内部共振峰保持 |
| Distortion／失真 | 柔和过载、硬削波、法兹三种曲线；驱动、音色低通、直流去除；二倍插值整形 | 不是 BOSS 音箱型号合集；简单过采样不能消除所有高频混叠 |
| Dynamics／动态 | 左右联动峰值侧链；软拐点压缩、无前瞻限幅、噪声门；攻击、释放、阈值、比率与补偿增益 | 限幅含输出上限，但不是真峰值／前瞻母带限幅器 |
| EQ／均衡器 | 低搁架＋中频峰值＋高搁架；三段 ±24 dB，中频 Q；图形控制点与旋钮同步 | 图示为 48 kHz 的线性频率响应；未实现硬件所有 EQ 模式 |
| Octave／低八度 | 两路立体声移调，低一与低两八度，独立音量与原声混合 | 共用相位声码器窗口；有固定算法延迟 |
| Auto Pan／自动声像 | 正弦声像运动，速度、拍同步和深度 | 当前只提供一种运动形状 |
| Panning Delay／左右抽头延迟 | 共用普通 Delay 缓冲／滤波内核；左抽头为 Time × Ratio，右抽头为 Time，完整延迟交叉反馈 | 左右布局是可解释的自研实现；官方手册没有公布精确反馈拓扑 |
| Phaser／相位器 | 六级一阶全通串联，调制中心频率，反馈和混合 | 没有复刻硬件所有级数／波形选项 |
| Flanger／镶边 | 亚毫秒起始的短延迟调制、反馈、左右相位差 | 没有通过零点的负延迟模式 |
| Sustainer／延音压缩 | 与 Dynamics 共用核心，默认更低阈值、较高比率和补偿增益 | 不是生成无限音的音源，也会抬升录入噪声 |
| Manual Pan／手动声像 | 左右声道平衡，中央保持原立体声，极端位置衰减另一侧 | 不等于把完整立体声折叠为一个声像点 |
| Stereo Enhance／立体声扩展 | 中侧声道矩阵：宽度 0 单声道、1 原始、2 扩展；保持单声道和 | 不从单声道输入虚构新的侧信号 |
| Tremolo／振幅颤音 | 正弦幅度调制，速度、拍同步与深度 | 不是重复触发 AHDSR |
| Vibrato／音高颤音 | 可变短延迟产生音高摆动，深度与速度 | 移动延迟会产生短延迟和边带，不是固定半音移调 |
| Step Slicer／步进切片 | 1～16 步音量柱，鼠标拖画，整周期拍同步，平滑门控 | 是控制序列，不是 MIDI 乐句；尚未提供硬件的所有步长／压缩参数 |
| Freeze／冻结延音 | 捕获约 90 ms 纹理，互补重叠窗持续播放；渐入、渐出、衰减和持续电平 | 是颗粒延音，不是频谱冻结；与按拍细分的 Roll 区别明确 |
| Chorus／合唱 | 立体声调制延迟，以相位差和混合产生增厚 | 没有提供硬件全部切频和音色子参数 |

### 音高效果的延迟

移调使用约 40 ms 量级的 FFT 窗口，取不小于目标的二次幂。在 **48 kHz 下是 2048 帧窗口，统一稳态与 unity 路径延迟为 2047 帧，约 42.65 ms**；44.1 kHz 下约 46.42 ms。展开编辑器按当前引擎采样率显示帧数与毫秒。固定 0 半音、关闭控制序列的 Transpose 使用原样直通。

低采样率仍保留最少1024帧窗口用于频率分辨率：16 kHz约63.94 ms、8 kHz约127.88 ms；低采样率并不保证音高处理延迟更低。

Electric 的清辅音、Harmonist 的原声以及音高效果内部的干湿声按同一窗口对齐。它们不因为音高比率接近 1 而忽然切到零延迟。各插槽的 FFT 运算时刻错开，但用零填充的初始窗口保持相同音频延迟；不能把“错开计算”变成“轨道错开播放”。

**声卡回环校准不包含这些 FX 窗口；目前没有跨轨道的自动插件延迟补偿（PDC）。** 多个音高效果串联会叠加延迟。对人声实时监听敏感时，应减少串联数量；Delay、Reverb 等刻意的空间时间不会被当作错误延迟抵消。

## 既有效果完善

- **Filter**：保留 LPF/BPF/HPF 与自研 Notch，改为 TPT 状态变量结构，避免直接型系数突变时状态含义改变；截止频率仍按对数平滑。驱动增益归一化只在参数改变时计算。静态响应图与实际音频以多频点比较，高 Q、快速扫频在 8～192 kHz 下做有限性与无分配检查。共享内核也用于 OSC 内部滤波。
- **Vocoder**：现在支持两类机架。分析包络仍逐采样跟踪，谱包络整形、共振峰插值和倾斜每 16 帧计算并插值，减少大量逐采样指数运算。Track Vocoder 用当前轨的声音作调制信号，载波可来自实时输入或每帧的 FX 前轨道快照，避免依赖轨道处理顺序或产生瞬时反馈。Input Vocoder 保留原有载波通道／轨道语义。
- **Delay**：Input 与 Track 共用同一个内核，Panning Delay 在其上增加抽头布局。支持直接／效果电平、0=FLAT 高低切、1～16 次反馈或手动系数；“次数”映射为指定次数后衰减至 −60 dB，不冒充未公开的硬件反馈曲线。缓冲上限仍为 2 秒；同步音符超过上限时界面提示实际截到 2000 ms。修复和测试继续覆盖 1 ms、高反馈及跨采样率连续调节。
- **Roll**：补齐 Input 路由，两类机架共用配置、参数编辑与 DSP。关闭时仍捕获最近前级声音；Serial 严格按槽位，Legacy 明确最后处理。保留 Roll1 的反馈释放与 Roll2 的有限／无限重复；完整周期与细分语义不变。缓存循环段衰减，避免每采样重复计算幂函数，反馈在段内修改仍立即生效。清轨、类型／bank 切换不泄漏原冻结音频，长度改变重新捕获，回到干声采用平滑过渡；新增1 ms/1⁄16短片段、实时反馈修改、Input Roll 旁路捕获／重新捕获、bank/type 清理、无实时分配和工程／音色预设往返回归。
- **Reverb**：两类机架和主输出均使用扩散＋反馈延迟网络。缓冲清空改为有效长度标记，不在实时线程遍历大块音频；频率／RT60／预延迟的既有测试保持。机架 Reverb 与主混响共享 DSP，不宣称是 BOSS 原厂混响拓扑。

## 主输出

音频／校准页包含主压缩和主混响开关，以及独立的完整编辑窗口。处理顺序为五轨推子后的和声＋打开 Input Thru 时的处理后输入 → 主压缩 → 主混响 → 输出保护。默认均关闭。

主效果改变最终听到的混音以及回放导出，**不写入各条循环轨道**。节拍器属于仅监听分支，在主输出之后加入；不会经主混响产生尾音或混入录音。

## 验证与性能限制

可运行 `cargo test --all-targets`。相关测试覆盖效果保存／加载、旧 Delay 手动反馈迁移、单声部检测、纯音移调、立体声相位、初始窗和重置、无实时分配、声卡采样率边界、母线处理和叠录余量。原生 UI 使用隔离的 `--offline --data-dir=var/...` 数据目录实际渲染。

最坏负载基准是同一 bank 的四槽在五条轨道上全部启用，即 **20 个 DSP 实例**。48 kHz、每块 128 帧的理论预算为 2.667 ms；本机 release 测量 3 秒音频得到：

| 20 个相同效果实例 | 总 CPU 时间 | 每块 p95 | 每块 p99 | 最大单块 |
|---|---:|---:|---:|---:|
| Transpose | 996 ms | 1.182 ms | 1.327 ms | 1.864 ms |
| Electric | 1345 ms | 1.506 ms | 1.692 ms | 2.018 ms |
| Octave（每实例两路移调） | 1862 ms | 2.179 ms | 2.409 ms | 3.590 ms |
| Dynamics | 150 ms | 0.148 ms | 0.264 ms | 0.408 ms |
| Reverb | 243 ms | 0.245 ms | 0.399 ms | 0.910 ms |

固定插槽相位错开 FFT 后，Transpose 的 p95 从集中处理时约 4.57 ms 降到本轮约 1.18 ms；初始零填充保证不因此改变各槽音频延迟。**20 个 Octave 的峰值仍超过 128 帧预算**，并且基准未加满 OSC、录音页与设备驱动工作。高负载时应从 256／512 帧开始，或减少同时启用的音高实例；不能用平均 CPU 或一次 p99 推断声卡必然不会丢帧。真实声卡、蓝牙链路、演奏听感和 BOSS 对比仍需要设备验收。

当前为了不在音频回调分配，各空槽和未激活 bank 也预备全部状态。Windows release 单个空 RenderCore 实测私有内存约 **251 MiB @ 48 kHz、994 MiB @ 192 kHz**，初始化约 78／361 ms，包含 Input Roll 预备缓冲，不含后续录入的音频页。直播引擎与回放／跳转引擎可同时存在，内存会相加。FFT 计划已按窗口大小跨实例共享；后续宜改为控制线程按实际配置准备处理器状态，以进一步减少空槽占用。

## 公开算法参考

- [W3C Audio EQ Cookbook](https://www.w3.org/TR/audio-eq-cookbook/)：三段均衡的双二阶系数与响应。
- [Vadim Zavalishin：The Art of VA Filter Design](https://www.native-instruments.com/fileadmin/ni_media/downloads/pdf/VAFilterDesign_2.1.0.pdf)：拓扑保持与状态变量滤波思路。
- [Cytomic：Linear Trapezoidal State Variable Filter](https://cytomic.com/files/dsp/SvfLinearTrapezoidalSin.pdf)：状态变量结构与可调系数的公开推导。
- [Faust misceffects](https://faustlibraries.grame.fr/libs/misceffects/) 和 [Julius O. Smith：Time-Varying Delay Effects](https://www.dsprelated.com/freebooks/pasp/Time_Varying_Delay_Effects.html)：调制延迟、变调与相关效果的公开结构。最终移调采用自研流式相位声码器；没有复制 BOSS、FL Studio 或 Serum 的未公开代码。
- YIN 检测原始文献：Alain de Cheveigné、Hideki Kawahara，*YIN, a fundamental frequency estimator for speech and music*，JASA 111(4), 2002。本实现将固定窗口的候选延迟计算分散到采样步，限制单次工作量。
