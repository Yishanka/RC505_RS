# Architecture

RC505 RS currently supports Windows x64 only. This file describes the implementation; installation and released binaries are covered by the [installation guide](INSTALL_UPDATE_CN.md).

## Ownership and scheduling

`engine/core.rs::RenderCore` is the single device-independent renderer. The output callback owns it; UI does not mutate track audio or advance transport. `SampleClock` uses a u64 frame counter and derives every beat boundary from the original rational tempo, avoiding cumulative rounding. Playback, capture, compensation tails, overdub and sequences use this clock. GUI state is a bounded `EngineView` snapshot.

Configuration defaults are pure data. Device enumeration is an explicit interactive startup operation, never part of project/preset conversion or offline replay. This also lets the regression suite run on Windows machines without audio devices.

The input callback sanitizes stereo frames and pushes them into an SPSC ring. The output callback adapts input clock drift with cubic interpolation, applies the optional stereo-linked input noise gate, runs track FX to obtain pre-fader carriers, processes Input FX, writes recordings/overdubs, applies faders and emits the master mix. Replay retains the pre-gate source; external-input audition uses the conditioned input, while physical calibration bypasses the gate. Monitor and loop audio share one processing domain. Queue starvation/overflow and callback duration are counted without callback logging.

Control messages are bounded (128). Parameters/runtimes are constructed outside the callback, swapped on receipt and retired through the worker queue. The renderer has no egui dependency. Its steady-state per-sample DSP uses prepared storage and no explicit mutex; this is not a claim that device startup, stream handoff, drivers or the complete callback are lock-free. Memory reclamation, WAV I/O and serialization run on workers. The allocation test covers five-track rendering, existing heavy FX, parameter exchange, snapshot sharing, overdub, undo and clear; it does not establish a hardware deadline guarantee.

## Physical output routing (0.2.5)

The global `follow_system_output` preference defaults to true, including migration of older preferences that contain only a concrete device name. A worker checks the Windows `eConsole` render endpoint every 500 ms. It compares opaque endpoint IDs, not friendly names or brands; fixed-device mode remains explicit. See Microsoft's [default endpoint API](https://learn.microsoft.com/en-us/windows/win32/api/mmdeviceapi/nf-mmdeviceapi-immdeviceenumerator-getdefaultaudioendpoint) and [endpoint identity API](https://learn.microsoft.com/en-us/windows/win32/api/mmdeviceapi/nf-mmdeviceapi-immdevice-getid).

Output handoff prepares a silent candidate stream, releases the old stream, and transfers the exact `OutputState` through a bounded queue. The callback owner returns its state at stream teardown; the teardown channel is never used during per-frame rendering. No snapshot reload or transport reset is involved. Loop buffers, pending actions, recording mode, effect state and renderer frame numbering remain owned by the same renderer. If an output is absent, its state is parked and input capture paused; replay capture is marked incomplete after loss of input.

The renderer stays at its original rate. A 64-tap, 256-phase windowed-sinc converter adapts only the physical output, with an exact bypass at equal rates. Coefficients are constructed outside callbacks; mono is downmixed and additional hardware channels are zeroed. Device changes invalidate loopback probes by a generation counter, preventing late results from being applied to a new route. Runtime driver teardown can still block or interrupt sound; this is not a guarantee against arbitrary driver failures.

## Audio pages and undo

`LoopAudio` stores stereo f32 frames in shared 8192-frame pages (storage granularity, not device buffering). Page tables reserve five-minute capacity per track. A dedicated worker supplies prepared pages. Snapshots/undo share references; subsequent writes obtain a fresh page and copy only that page. Old references go to a bounded retirement queue. Pool exhaustion stops the affected recording and reports it, instead of growing a Vec in the callback. Five tracks at 48 kHz, five minutes each need about576 MB for one full audio generation; undo/COW snapshots can increase peak memory.

Each track keeps up to eight recording/overdub/clear transactions using preallocated page tables. Each undo/redo stack evicts oldest entries above 2048 referenced pages (128 MiB), while retaining at least one entry. Long loops can therefore keep fewer than eight steps; a single latest step can exceed that budget. New writes clear redo. Snapshot save persists both stacks, reusing WAV assets with identical immutable page identity. Legacy single-level undo remains only for renderer 2 compatibility. Reverse and One Shot suppress overdub. Stop may be immediate, loop-end or fade; a second stop bypasses a pending playback stop. Recording finalization waits for the configured capture tail, preserving exact target length.

## Persistence and replay

`project.rs` retains the legacy JSON parameter codec and explicit defaults. New optional fields include track options, independent fader rates, routing, sample calibration and snapshot reference. Delay Mix migrates to independent Direct/Effect levels. Reverb percent high damping maps to the previous frequency before conversion to Hz. Unique file identifiers survive rename.

`session.rs` writes version 4 asset bundles: config, five tracks, both history stacks, legacy undo, sample rate, lengths and SHA-256. Empty audio uses a null reference without an empty WAV. Versions 2/3 remain readable; version 2 bundles migrate the previous undo into the correct undo/redo stack. A new revision is staged, flushed and renamed before updating the project pointer. Existing versions and a prior project JSON backup remain. Missing/corrupt data fails before replacing the runtime. Index recovery and a project trash service are centralized here; the launcher no longer owns an independent project database. A per-data-folder editor lock makes a second editor read-only.

`replay.rs` stores an initial audio/config bundle, dry input float WAV and ordered JSONL events `{frame, sequence, kind, sample_assets?}`. Begin Take requires stopped tracks and swaps in prepared clean DSP state; this makes the initial condition explicit instead of omitting old effect tails. Commands are logged at the sample where the renderer accepts them. The worker detects input gaps and queue loss. A completed take has hashes and a renderer version; incomplete takes cannot masquerade as valid replay. `replay/assets.rs` strips immutable OSC PCM from repeated config events and stores SHA-256 addressed float assets inside the replay folder. References preserve sample metadata and are checked against file length, hash and canonical containment; readers share decoded `Arc<SampleAsset>` values. Initial bundles still embed the starting samples once.

Renderer 4 writes the first configuration event as a complete baseline, then `ConfigDelta` events containing a configuration revision and typed-path replacements. The patched document contains both configuration and its sample-reference table, so unchanged phrases and sample references are not repeated for each fader movement. `replay/delta.rs` validates revision order, existing paths, container types, duplicate/overlapping operations and fixed rack/track dimensions; old complete `Config` events remain supported. The `Source` event list retains sparse deltas rather than expanding all configurations. Readers keep one validated working baseline and apply events sequentially, including when seeking from the initial state. A dedicated scalar fader path avoids repeatedly converting unchanged note trees through JSON; it preserves the same sample timestamps and command ordering.

Playback and explicit WAV export run the same `RenderCore` at the original sample rate. `replay/streaming.rs::Machine` streams dry input and applies operations at integer source-frame positions. A worker feeds a fixed 4096-frame SPSC audio queue; the audio callback only reads samples and atomics. No full output file or full-output PCM vector is created for playback. Pause stops consumption; a seek revision invalidates old queued samples, reconstructs renderer and output-converter history off the callback, then publishes the exact target view before resuming. Reconstruction can take time for long recordings; newer seeks and closing supersede pending work. Equal-rate and converted-output tests compare post-seek samples with uninterrupted replay.

Pause/import reconstructs the chosen source frame into an unsaved working copy with stopped tracks, preserving partial recorded buffers and bounded history. Any existing or new project may be selected with an explicit overwrite explanation. Its saved file is not replaced until the user saves, so Discard restores that baseline. `replay/library.rs` migrates valid old project replays to the global `data/replays` library before project deletion; source project identity is provenance only. Export is explicit, goes to the independent exports folder, and has a direct delete action.

Renderer 10 accepts renderer 2–9 recordings with an algorithm-change notice. Removed Filter modulation is no longer applied, including in old replays. Config events retain their original raw JSON baseline for delta application, then decode into current configuration; old source files are never rewritten. Versions below 5 disable PDC; versions below 7 retain the previous single-reference recording path; versions below 8 bypass the input noise gate. Version 7 separates clocked generation from physical-input compensation without altering the monitoring graph. Inputs/events remain untouched; historical fixed-note/one-level-undo flags are retained where supported, but the evolving OSC/FX implementation is not a frozen historical binary. Current-version live/replay fixtures are bit-exact; they do not establish compatibility with historical releases or cross-compiler/CPU bit identity. Playback bounds are 30 minutes, a 512 MiB event log, 100,000 events and 256 MiB decoded sample assets.

For source-aware capture, the normal input chain produces W; a separately prepared, continuously warm chain suppresses generator output/capture/phrase commits but preserves dry levels and downstream processors, producing X. G=W−X is the internally generated contribution, including nonlinear interaction with the input. External recording writes G to source frame n−Li and X to n−(H+Li+M), with independent monotonic cursors. Both offsets are latched per recording/overdub pass; changing H affects later passes. Incomplete opposite-sign sums are not prematurely clipped. The completed prefix can play at the musical boundary while external capture drains, so even a pure-OSC loop shorter than H is not artificially postponed. Monitoring remains W; H does not change it. Internal-reference and zero-extra-offset paths use the original W write directly. Shadow preparation/retirement follows existing control-thread ownership; costs are measured rather than assumed free.

Delayed graph changes retain their original sample-stamped Config request. The callback also emits a scalar `PdcApplied { requested_at, applied_at }` through the bounded worker queue after the applying sample. The log places that marker at `applied_at + 1`, before any newly accepted commands at that boundary, and stores both timestamps relative to the take origin. Streaming, seek reconstruction and export independently let the same Core decide the safe point, then validate any marker against the preceding process result; they do not force DSP changes from the marker. Old/hand-authored fixtures may omit markers, but present, mismatched or duplicate markers fail playback. Losing a marker to queue overflow invalidates capture instead of silently claiming exactness.

## UI and installation

`presets::SoundCandidate` holds validated preset text, a pinned target and input source identity outside ProjectData. Browsing changes no live parameters. An explicit candidate audition prepares a private processor; the callback still runs the formal Core and track writes, but temporarily replaces only the monitor result. Stopping restores formal monitoring, and capture/calibration/player guards forbid starting a candidate there. Ordinary live configuration synchronization never overwrites candidate audition parameters. Apply uses the retained text and preserves musical data / bypass state; Cancel or leaving the target drops the candidate.

Audition requests reuse the existing command queue and carry UI-side expectations against a callback-processed command count. Stale `auditioning=false` cannot cancel an unacknowledged start, and a short note that already finished before the first UI poll is still acknowledged correctly. Failed Stop enqueue preserves playback/candidate state; Apply/Cancel do not proceed after that failure. A successful audio-bridge replacement resets expectations to its new diagnostics epoch. Candidate output remains separate from formal recording throughout.

`config/automation.rs` stores one optional lane per FX slot, bounded to 64 normalized points and eight bars at 960 PPQ. `dsp/automation.rs` validates and compiles each segment into a 257-value physical-unit table on the control side; a 128-entry Weak cache reuses identical immutable plans. Callback lookup uses integer source-sample ratios, binary segment search and table interpolation, with no lock, allocation, JSON or parameter-object reconstruction. The source ClockPoint has already passed through the existing PDC history. Filter base cutoff/Q, Delay time/feedback/effect level and Reverb decay/wet are the only destinations; existing DSP smoothing remains. Renderer 10 uses all 256 table intervals; older renderers use the original 64 intervals. Standalone Filter sweep/step-gate/envelope state has been removed. Periods support 1/16 to 32 beats, with one-tick editing and node-preserving rescaling. Incompatible types disable but retain lanes. Project codecs, single-slot patches and replay config deltas carry them; editor histories and audition state remain transient.

`app/shortcuts.rs` defines stable command IDs, default chords and persisted overrides in global `keyboard.json`. Dispatch, editable key configuration and hints share this table. Exact modifiers distinguish bindings; toggles ignore repeat while faders and hold effects use held state. FX and master editing keep recording, FX switches and faders active; local arrows, Delete and edit chords are filtered out of performance dispatch. Text entry, menus, shortcut assignment, help and replay own their input. Scene changes still invalidate hidden accessibility focus.

Input Thru is project data with a legacy default of enabled. The Core continues input DSP and track writes, then applies a short monitor-only gain ramp before summing with loop outputs. It neither mutes loop playback nor changes record/finish actions. Master processors follow the mix and precede final clipping; metronome/audition remain on their established separate monitor path.

`app/actions.rs` shares commands between mouse and keyboard. F6, F7 and F8 select top/left/right; navigation registers current-frame controls. Up/Down selects a control and Left/Right edits it; note/automation canvases own their local arrows. `ui/parameter_input.rs` separates typed/mouse precision from unit-specific performance steps (1 ms, 0.5 dB, 1 percentage point), with timed holding and Enter/Escape entry. Explicit text roles protect newly focused fields before egui emits IME geometry. Moving between live panels preserves a held fader ramp; clear gestures are cancelled across contexts. Momentary FX retain their original bank/track/slot so release restores the correct target.

Navigation requests are deferred until the current scope has drawn its controls. The expanded editor owns a separate focus scope; it never traverses compact-panel IDs. A raw-input hook removes scoped navigation from egui's early native traversal, then restores events, held state and repeat flags for the app/widgets. Focus loss disarms old navigation holds until release. Scene changes clear hidden focus, except the still-visible FX picker when only its type changes. This preserves the Windows AccessKit invariant that the focus node exists in the current accessibility tree. The process-isolated UI regression runs the production input hook, checks accessibility, repeated small-panel traversal, text isolation and dialog/focus guards. Unexpected panics are logged to the chosen data directory's `logs/last-panic.log`.

Recording/overdub beat indicators derive their four-beat phase from the engine's elapsed sample count. Piano roll owns a bounded two-axis viewport, with sticky keyboard/ruler headers and explicit middle-button panning; scrolling never doubles as note dragging.

On Windows, `performance_keys.rs` bridges egui0.27's dropped/translated Shift symbols using key state for the explicitly bound performance keys. It checks both application focus and foreground process identity before polling, suppresses held keys when returning from editing, and modifies only the command router's input copy. The original text input stream is unchanged.

`ui/theme.rs` supplies fonts/colors; `performance.rs` uses fixed quick-panel geometry and internal scrolling. `editor.rs`, `parameters.rs` and `piano_roll.rs` edit the same config with pinned bank/slot identity. Legacy painted screens and the old wall-clock Track/Metronome scheduler are removed.

`app_support/paths.rs` resolves explicit `--data-dir`, then executable-adjacent `install-settings.json`, then the legacy AppData fallback. The installer defaults data to the program's `data` folder. `maintenance.rs` performs copy/verify migration before audio or GUI startup. `updater.rs` uses an embedded PowerShell helper to validate GitHub release metadata, download and hash the installer, and wait for normal app exit before installation. No updater token or GitHub credential is distributed.

## DSP scope

Legacy Input FX: input + normalized Oscillator bus + MyDelay bus → Vocoder → Filter → Reverb. Serial mode executes A→D, with generators added at their slot. Track FX follows slot order. Vocoder carriers are after Track FX and before faders. Filter coefficients update at an eight-sample control interval while moving; Reverb feedback coefficients at32 samples. Fixed parameters use cached coefficients.

Existing DSP/control semantics are independently implemented from public references. Hardware A/B, long-running driver stress, physical loopback and keyboard rollover remain real-device acceptance work. See [validation](VALIDATION.md) and [references](RC505_REFERENCE.md).


## OSC, notes and sound assets (0.4)

New captured/imported samples are temporary. `ProjectData` retains full PCM for runtime transfer and deterministic replay; only `save_project_data` and `save_snapshot` call `persistable_data`, which omits temporary PCM. Explicit sound-preset save writes a self-contained preset and marks `SavedSampleRef` (relative preset name, SHA-256 and source metadata). Project files retain the reference and their own current controls. Project loading resolves PCM on a worker without replacing those controls; missing/changed references remain visible and removable. Old embedded data defaults to already-saved rather than being discarded on migration. Replay playback needs no sound library: initial PCM and later source assets stay inside the take. Import into a different library drops unusable references and exposes that PCM as a temporary sound for explicit local saving.

Snapshot format 4 uses null for empty track/history audio while preserving undo-step positions. Nonempty silent loops retain duration and still require an asset. Readers accept formats 2/3/4; old saved audio is not automatically deleted. Explicit exports alone create a rendered master WAV.

`NoteConfigs` now owns an authoritative bounded event clip (2048 notes, 8 bars, 960 PPQ). `NoteEvent` has stable ID, start, duration, pitch and velocity; pitch indexing remains C4=48 so old frequencies do not shift. `NoteClip.ppq` is explicit; absent means legacy 12 PPQ, migrated by ×80. Old single-note arrays are derived compatibility views only. A sparse off-before-on boundary sweep compiles the active voice schedule outside the callback; a bounded Arc cache reuses it across unrelated parameter changes. No 30,720-element array of per-tick voice vectors is built.

Each input slot has a persistent source ID. Switching away from OSC parks its clip, including through project save/reload; selecting OSC restores it. Sound preset version 2 excludes OSC clips and source IDs; loading version 1/2 sound presets preserves the destination clip. Separate `clips/` files save independent phrases, copied on load/paste. There is no implicit shared-edit link, DAW playlist or Performance bundle. Slot moves preserve identity by moving the slot object; no dedicated rearrangement UI is introduced.

Unified OSC covers basic waves, synthetic vowel waves, normalized captured/imported waveforms and full-sample playback. Up to 16 prepared voices per active source contain independent phase, velocity, AHDSR and filter state; fixed storage bounds live voices to 64 across the four active slots. Private audition adds at most 16 monitor-only voices. Note Off is keyed by note ID/cycle; deterministic voice stealing prefers released/quieter/older voices and uses a short transition. Mono is a scheduler policy and does not modify stored chords. Optional Mono Legato follows last-note priority and preserves envelopes and LFO phases while notes overlap, including returning to an older held note. The sparse boundary compiler marks continuity from the full active note set, not only the audible voice. Optional 0–2000 ms glide interpolates log frequency over an exact bounded number of samples, with overlap-only/all-notes modes; no per-sample allocation or note-on phase-table rebuilding is introduced. New fields default to Legato off/glide zero and preserve old patches.

The OSC-BOT control completion adds three software-defined sources: a DC-removed 25% pulse rendered from harmonic mip tables, a true two-phase saw pair at ±7 cents (PolyBLEP, fixed averaging/headroom), and a warm saw whose partial amplitudes follow `1/n^1.35` before DC removal, peak normalization and mip filtering. No noise/sub generator or general unison/matrix was added. Existing enum values and patch defaults are preserved. Optional `input_mod_sens` controls amplitude from the shared live-input peak envelope: `clamp(envelope * 4 * 10^(0.48*sens/20), 0, 1)`, with a roughly 5 ms one-pole transition, multiplied after the voice AHDSR. None is exactly neutral; private audition disables this external dependency. This is an explicit software interpretation of MOD SENS, not an undocumented BOSS mapping. Independent `dry_level` defaults to 1. Serial routing applies it per source slot; Legacy routing multiplies enabled OSC dry levels only on the original input, preserving the existing parallel OSC wet sum/normalization. Wave/level/envelope events replay through the same configuration acceptance and source clock.

Sample assets are immutable Arc PCM, bounded to 96,000 mono frames. WAV loading, centered 64-tap/256-phase sinc conversion to 48 kHz, cycle/root analysis and native file selection run outside the audio callback. One-shot capture uses a UI-allocated, bounded atomic mailbox (up to 384,000 frames at 192 kHz); the callback publishes completion, a worker prepares the sample, and normal configuration acceptance makes it audible. Embedded project/patch samples are validated and rehashed at entry; a bounded Weak identity cache avoids rescanning unchanged immutable PCM on every parameter event. UI fingerprints retain sample metadata/hash while excluding PCM serialization.

Sample voices bind an immutable material generation at Note On: PCM, prefiltered sample levels, periodic wave tables, sample mode, region, root frequency and loop behavior. Replacing or recapturing material affects later notes; held/releasing voices continue their original source. Mono legato keeps its envelope semantics, but a new note uses the new material with the existing short voice transition. A prepared 17-slot pool bounds ownership to sixteen active generations plus the current source. Voices keep small indices rather than owning Arcs, so ending/stealing/resetting a voice never releases the last sample reference. Runtime exchange moves unused materials into the outgoing runtime's fixed retirement array, which follows the existing control-envelope worker retirement path. Completed material may stay in the bounded pool until the next config exchange or worker-side engine retirement. OSC removal also resets voice references and transfers all obsolete generations. Live replay and seek use the same lifetime rules; this fixes the older sound at material-replacement boundaries.

Sample/vowel waveforms use off-thread 2048-point FFT-generated harmonic mip tables. Full samples use prefiltered half-rate levels and fractional read positions. Two prepared LFOs have separate Free/Retrigger phase state, synchronized beats/Hz, curves and volume/cutoff/pitch destinations. Same-target volume factors multiply; pitch/cutoff ratios multiply (equivalent to adding semitones/octaves). Disabled LFOs are exactly neutral, and volume modulation cannot bypass the per-voice amplitude envelope. AHDSR timing/curvature nodes and numeric controls share the same parameters. `ui/envelope_view.rs` owns fixed-span per-editor view state (100 ms/500 ms/1 s/5 s/30 s plus manual offset); parameter edits never recompute its scale. Old MyDelay files migrate into OSC Sample, but missing historical capture PCM cannot be recovered and changed algorithms are not claimed bit-identical.

Remaining deliberate limits: AHDSR has fixed semantic nodes rather than arbitrary added envelope stages (the LFO curve supports added points); two LFOs each expose one target rather than a general modulation matrix; samples are mono and at most two seconds. No MIDI/MPE, unison engine or global arrangement is implemented.

`phrases.rs` owns explicit link groups independently of source identity and sound patches. Copies fork clip identity; linked sources share normalized note content while ordinary edits preserve each source's phase. A source has one active Clip and at most one queued Clip. Both schedules are prepared on the control thread; `dsp/oscillator/phrase.rs` changes scalar state at the next old-loop boundary, including inactive banks, without allocating on the callback. The engine exposes source-keyed applied serials so UI acknowledgement promotes the prepared phrase without retriggering voices. A stale snapshot for a moved source cannot acknowledge another slot's request. Replay import promotes an already-applied queued phrase even when its original UI acknowledgement has not yet occurred. Pending switches persist through stopped saves and wait for a resumed loop; new stopped/bypassed loads are immediate.

Piano selection uses stable note IDs, bounded 64-step local history, group transforms clamped as a unit to loop and pitch boundaries, and independent selected-note/full-phrase clipboards. Ctrl+drag and group paste generate fresh IDs and never implicitly lengthen the loop. Canvas, selectors and toolbar controls join the common navigation scope; local editing keys do not suppress unrelated performance commands. Clicking a note creates a small standalone prepared oscillator voice for approximately 250 ms plus release; it never changes project parameters, formal clock, track buffers or replay input. Finished audition state is reclaimed by the worker.


## Monitoring and calibration (0.2.7)

`dsp/stereo_enhance.rs` decorrelates the high-passed mid through two fixed pairs of short Schroeder allpass filters, subtracts their outputs into an added side signal, then optionally filters the combined side. Mid is never delayed: reconstruction is M±S, so stereo-to-mono summing preserves it before output clipping. Four cascaded 200 Hz high-pass poles protect low-frequency centering. Allpass memory is allocated at prepare; reset invalidates its history logically rather than clearing delay buffers in the callback. Enable/depth and optional cut transitions are smoothed. Dedicated `enhance_*` fields avoid interpreting unrelated historical delay high-cut values; legacy mode remains off. The public allpass structure follows [Julius O. Smith's Physical Audio Signal Processing](https://www.dsprelated.com/freebooks/pasp/Allpass_Filters.html); this is not a reconstruction of proprietary BOSS DSP.

Formal transport, metronome and private audition are separate state. Starting the click starts transport; disabling the click leaves transport running. Audition has an independently prepared DSP runtime, pinned bank/slot/track and private sample counter. It bypasses slot enable and trigger thresholds. Callback mixes the precomputed click and audition after `RenderCore::process`, so neither enters track buffers or offline replay output. Starting capture retires audition and resets formal DSP/transport. Capture eligibility checks stopped tracks, not the global transport flag.

The final output feeds an 8192-frame SPSC visualization queue. A dedicated worker runs stereo Hann-window radix-2 FFTs at about 30 Hz (4096/8192/16384 samples by renderer rate), merges channel power without phase cancellation, maps 64 logarithmic bands and smooths release. Twiddles, permutation and work buffers are prepared off-thread. Callback work stays constant and may drop visual samples instead of waiting. Disabling the background stops sample submission and FFT work; fully silent windows skip FFT.

Calibration first persists a monitoring guard, then requests silence. Only after callback acknowledgement may the user confirm electrical loopback and request probes. Completion/failure never restores monitoring. Output handoff preserves the guard; startup reloads it. Explicit cable-disconnected confirmation clears it. Physical sockets and hardware direct monitoring cannot be detected by the application.


## Replay presentation and appearance

The simulation worker publishes bounded-rate `EngineView` snapshots plus immediate operation/configuration changes. `ui/replay_panel.rs` owns a boxed, isolated display configuration and editor; it consumes views only up to the source-frame cursor actually heard and exposes draggable seek/pause/import controls. Exact target state is separately published on seek even when output conversion has consumed beyond that point. Immutable sample PCM is excluded from UI focus-change JSON comparisons. The shared performance workspace remains read-only; the live model is restored before configuration synchronization. Closing retains the live project's buffers and parameters. Old replays have no pointer/focus/window-layout history. `replay/visuals.rs` remains useful for UI fixtures and focus detection; ordinary export does not build a full visual timeline.

Replay delete/discard validates canonical managed paths, then renames the folder into the global library's `trash`. Restore uses a fresh identity and never overwrites a live replay; exported WAVs stay independent and may be permanently deleted from their own list. Project deletion uses the existing project trash after replay migration succeeds. Failed migration stops deletion rather than making recordings disappear with a project.

ThemeColor is a global, serde-defaulted launcher preference (Mint/Rose/Ember). The UI palette lives in `theme.rs`; custom graphics read the current palette from egui instead of fixed accent constants. It is not part of project configuration or replay events, and the icon is unchanged.
