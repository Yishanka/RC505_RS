# Harness Requirements Router

## 1. 用途

本文件是后续所有开发任务的**唯一入口文档**。

任何开发开始前，必须先阅读 `AGENTS/REQUIREMENTS.md`，再按本文件路由继续阅读对应要求文档。

---

## 2. 固定执行顺序

每次任务默认按以下顺序读取：

1. 先读 `AGENTS/REQUIREMENTS.md`
2. 再读 `AGENTS/requirements/10-global.md`
3. 再按任务类型读取对应专项要求

---

## 3. 任务路由

### A. 新增功能 / 功能扩展

继续阅读：

`AGENTS/requirements/20-func-dev.md`

适用场景：

1. 新效果器
2. 新参数组
3. 新 UI 交互
4. 新运行时能力
5. 新工程存档字段

### B. 逻辑问题修改 / 功能普通修改 / 功能删除

继续阅读：

`AGENTS/requirements/30-debug.md`

适用场景：

1. 修 bug
2. 改已有逻辑
3. 删除功能
4. 修复参数行为
5. 修复存档兼容问题

### C. 架构调整 / 命名整理 / 函数拆分 / 文件拆分 / 风格统一

继续阅读：

`AGENTS/requirements/40-refactor.md`

适用场景：

1. 重命名
2. 拆模块
3. 拆函数
4. 清理重复逻辑
5. 调整代码组织方式

### D. 混合型任务

如果一个任务同时包含多类内容，必须按主任务拆分，并读取全部相关专项文档。

---

## 4. 入口层面的硬约束

无论任务类型如何，以下规则始终成立：

1. 提示词没有明确要求时，不要修改 `AGENTS/PLAN.md`
2. 必须先分类任务，再实施修改
3. 不能只做局部补丁而忽略必要链路
4. 发生改动后，必须写入对应文档目录
5. 最终汇报必须说明任务分类、改动范围、验证方式、文档位置、剩余风险

---

## 5. 文档目录映射

1. 功能开发：写入 `AGENTS/funcdev-docs/`
2. 逻辑修复 / 功能修改 / 功能删除：写入 `AGENTS/debug-docs/`
3. 架构 / 风格 / 重构：写入 `AGENTS/code-docs/`

音频项目可以不强制提供自动化 test case，但文档中必须提供可执行的人工验证方法。
