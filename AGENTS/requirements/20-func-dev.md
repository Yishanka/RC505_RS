# Feature Development Requirements

## 1. 适用范围

当任务属于新增功能或扩展已有功能能力时，必须遵循本文件。

---

## 2. 先拆清楚功能

不能直接按一句模糊描述开写，至少要在实现过程中明确：

1. 功能名称
2. 功能用途
3. 子功能列表
4. 每个子功能的参数
5. 参数类型、范围、默认值
6. 参数影响哪一层
7. 是否需要保存到工程文件

如果是效果器或音频模块，还要额外明确：

1. 作用对象
2. 开关方式
3. 参数如何驱动 DSP
4. 是否参与录音、回放、叠录或总线处理

---

## 3. 默认要求全链路实现

除非经过代码分析后确认某层不适用，否则功能开发默认需要检查并完成以下链路：

1. UI：可见、可操作、可反馈状态
2. Config：参数结构、默认值、序列化入口
3. DSP：算法或处理逻辑本体
4. Engine：把配置与 DSP 接入运行时处理链
5. Project：可保存、可载入、兼容已有工程

如果某层不需要改，必须在文档中写明原因。

---

## 4. 功能开发的落盘要求

完成后必须在 `AGENTS/funcdev-docs/` 新增文档。

建议文件名：

`YYYY-MM-DD_<feature-name>.md`

文档至少包含：

1. 功能目标
2. 子功能与参数说明
3. 涉及的代码层级
4. UI / Config / DSP / Engine / Project 分别做了什么
5. 与旧逻辑的兼容性说明
6. 手工测试步骤
7. 已知限制或后续迭代点

---

## 5. 完成标准

只有满足以下条件，才视为功能开发完成：

1. 代码实现完成
2. 必要链路完整
3. 参数定义明确
4. 工程保存与载入逻辑已处理，或已说明不需要
5. 文档已写入 `AGENTS/funcdev-docs/`
6. 提供了至少一套人工验证方法
