# Refactor Requirements

## 1. 适用范围

当任务不涉及新增功能或功能行为变化，而是以下类型时，必须遵循本文件：

1. 命名调整
2. 函数拆分
3. 文件拆分
4. 模块重组
5. 代码风格统一
6. 重复逻辑抽取
7. 结构清理

---

## 2. 默认目标

重构类任务的目标是改善结构，而不是顺手改功能。

除非提示词明确要求，否则默认：

1. 不改变外部行为
2. 不混入新的功能需求
3. 不把功能修改伪装成重构

---

## 3. 重构要求

在实施时，必须尽量说明：

1. 为什么要改
2. 旧结构的问题是什么
3. 新结构如何更清晰
4. 行为是否保持一致
5. 是否有必须引入的兼容性调整

如果确实引入了行为变化，必须在文档中明确写出。

---

## 4. 重构后的文档要求

完成后必须在 `AGENTS/code-docs/` 新增文档。

建议文件名：

`YYYY-MM-DD_<refactor-name>.md`

文档至少包含：

1. 改动目标
2. 旧结构问题
3. 新结构说明
4. 命名 / 文件 / 模块变更
5. 是否有行为变化
6. 手工验证方法

---

## 5. 完成标准

1. 结构问题已被解决
2. 不涉及的功能行为未被误改
3. 文档已写入 `AGENTS/code-docs/`
4. 给出了验证方法
