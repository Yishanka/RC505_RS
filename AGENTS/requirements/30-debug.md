# Change And Debug Requirements

## 1. 适用范围

当任务属于以下场景时，必须遵循本文件：

1. 修 bug
2. 功能逻辑问题修改
3. 功能普通修改
4. 功能删除
5. 参数行为修正
6. 存档兼容或载入问题修复

---

## 2. 必须先明确问题

在动手修改前，必须尽量澄清：

1. 问题现象是什么
2. 触发条件是什么
3. 受影响模块在哪里
4. 根因大概率在哪一层

不能在未定位范围的情况下盲改大段代码。

---

## 3. 修改要求

1. 先定位到具体代码位置
2. 修改问题本体，而不是只绕开表象
3. 删除功能时，要同步清理无效 UI、无效配置、无效保存字段和无效运行时入口
4. 修改已有功能时，要同步检查 UI、Config、Engine、Project 是否仍一致

如果修的是音频逻辑，还应额外检查：

1. 参数是否仍能被 UI 正确驱动
2. DSP 与 Engine 的调用顺序是否被破坏
3. Project 载入旧数据时是否会出现不兼容行为

---

## 4. 任务完成后的文档要求

完成后必须在 `AGENTS/debug-docs/` 新增文档。

建议文件名：

`YYYY-MM-DD_<issue-name>.md`

文档至少包含：

1. 问题描述
2. 复现方式
3. 根因定位
4. 修改方案
5. 影响范围
6. 手工验证步骤
7. 是否还有残余风险

---

## 5. 完成标准

1. 问题或修改目标已被明确
2. 代码已改到正确层级
3. 无效逻辑已同步清理
4. 文档已写入 `AGENTS/debug-docs/`
5. 提供了复现与验证方法
